# Members and groups

These pages are for server managers. They control the server’s working data; they do not change a person’s global Logi account.

## Members

### Connected websites

A website can read a minimized member directory using its own explicitly scoped
`member-summaries` API grant. Member types, status, paused state and groups remain
managed in Logi. This read does not authorize website administration or public
publication. Websites must obtain their own profile/publication consent and
bind it to the exact member and native user IDs; matching a nickname is not a
valid identity link. Notes, pause reasons and Discord role IDs are excluded.

Collected player facts have a separate `player-stat-summaries` grant. They cover
stored HLL/Warcon server sessions and only attribute a player through a current
verified Steam account and matching game membership. Unknown metrics remain
unknown, and the displayed collection is not a career total. Disconnecting the
verified account or changing membership invalidates website synchronization.

The **Members** page lists people known to the workspace. Managers can view a person, create a record where the workflow allows it, and manage server-specific assignments. Carefully distinguish the person’s identity from their roles and groups in this one server.

When you type platform IDs for a member, Logi checks each comma-separated ID as
you type. A long number that is not a 17-digit SteamID64 starting with 7656119,
a malformed `epic:` ID, an ID longer than 64 characters, or an ID already linked
to another player is marked under the field and blocks saving. An ID listed
twice is saved once. Write Xbox and PlayStation IDs as `xbox:…` or `psn:…`.

**Make admin** and **Remove admin access** on a member's page change who can
manage the clan in the dashboard; both ask for confirmation first. Admin access
granted by a Discord role is not removed this way. **Remove assignment** also
asks first: it deletes the member's assignment, groups and membership status in
this clan and removes the Discord roles Logi manages for them, while their match
history stays.

The available maintenance actions can include importing Discord members, linking missing Discord IDs, linking platform IDs, merging duplicate records, and cleaning duplicate player statistics. Use these only after checking the affected records: they change or combine real server data.

<Callout type="warning">
    Merge and deduplication actions can be difficult to undo. Confirm the source
    and destination records, and avoid using bulk maintenance tools as a
    substitute for checking individual data.
</Callout>

### Assignment fields, in plain language

Each person can have one assignment **per workspace and game**. The assignment
type can be **member**, **reserve member**, or **mercenary**; its status can be
**pending**, **recruit**, or **active**. A primary group is optional, and
secondary groups are optional additional classifications from the same game.
The same group is not kept twice: if it is primary, Logi removes it from the
secondary list.

This means one person may be an active HLL member and a Vietnam recruit (or a
Wardogs mercenary) at the same time. Choose the intended game before editing an
assignment. Their Logi profile, Discord account, and linked platform accounts
remain one shared identity and are linked only once.

An active member or reserve member is counted as a workspace member. A recruit is also counted as a member for this purpose. A pending assignment is not. An active mercenary is recorded separately and does not become the person's primary workspace membership.

Changing or removing an assignment rebuilds the workspace membership summary and refreshes open match rosters. A person who is not otherwise tracked by an open match is removed from its roster; a tracked attendee is placed in reserves, while a tracked non-attendee is placed in **not attending**. Check affected rosters after changing membership.

### Bulk member tools: what they do and do not do

Authenticated assignment changes and the membership-status migration now queue
durable membership-role operations. Check **Settings → Membership → Role changes** for the actual Discord outcome, current reason and recent attempts.
Retries recheck the original actor's current permissions; saving assignment data
does not mean the roles have been applied. Unlinked players remain editable, with
an explicit denied role operation until their Discord identity is linked. Legacy
API assignments and imports remain data-only and cannot mint role authority.

Attempt history records an interrupted attempt as **Superseded** when a newer
request replaces it. When the bot recovers an expired attempt, that attempt shows
**Retry scheduled** with `lease_expired`; exhausting six attempts shows **Failed**
with `attempt_limit`. These labels describe the attempt's outcome, not a promise
that another attempt is still waiting. Check the operation's current status above
the history. A previously verified attempt keeps its **Applied** result even if
the overall request is later superseded. Attempt times are start times in UTC.

The server **Settings** page contains bulk tools for managers. These tools apply to the game selected in the configuration scope; the Discord-member import has its own target-game selector. Treat the selected Discord role as a filter, not as a permanent relationship between Logi and Discord.

### Merging duplicate people and statistics

**Merge users** keeps the selected primary record and deletes the secondary record. It combines unique platform IDs, management and mercenary workspace lists, score records, and groups. Where both records already have an assignment in the same workspace, the primary assignment wins for type, status, category, and primary group; secondary groups are combined. The merge also rewrites affected event attendance, sign-ups, absence notices, rosters, stratmap authorship, ticket/application records, platform-link tokens, and player statistics so they point to the primary person, removing duplicate entries where possible.

This is a global data operation, not merely a change to the currently open Members table. The selected primary name, avatar, Discord ID, and primary membership normally take precedence when both records have values. There is no undo button; verify the records before confirming.

**Deduplicate player statistics** is available only for Hell Let Loose events belonging to the selected workspace. For a duplicated event entry, it keeps one match record per person/event and recalculates the affected people's performance summaries. It can delete now-empty statistic documents. It does not repair wrong source data or decide which of two conflicting match records is factually correct.

### Player statistics and trends

On a member's assignment detail, HLL and HLL Vietnam show kills, K/D, deaths,
offense, defense and support. Wardogs shows kills, K/D, deaths and money
(money earned or lost while playing), with a money chart instead of HLL effectiveness.
Other games hide gameplay stats. K/D always displays two decimal places,
including whole ratios and chart tooltips. Averages use the ten newest stored match records for that person
(or fewer when fewer are available) in that workspace and game. Hell Let Loose
and Wardogs records, trends, match histories, scores, and ratings do not mix.
Older records with no game are Hell Let Loose. The all-time match count shown
nearby is not the denominator for those averages. Records with the same
scoreboard source URL are treated as the same match in the detail view; if no
source URL exists, Logi falls back to a combination of map, end time, and
statistic values to avoid showing an obvious duplicate.

The performance charts are separate, per-workspace history snapshots. They are
built from up to ten recent recorded non-training events that have imported
match statistics or a confirmed Wardogs source, and from players assigned to that workspace at refresh time.
They can be empty or stale until qualifying result data exists and a history
refresh has run. They are useful trends, not attendance evidence or a complete
career record.

## Groups

Groups organise people for one game in your community and can have a name,
description, and hierarchy. They are used only by assignments and event sign-up
choices in that same game.

Select your clan and game, then open **Players › Groups** in the left menu.
This entry is visible to clan managers. For Wardogs, this is where you manage
the catalogue behind sign-up choices such as Infantry, Builder or Tank. The
names are editable clan data, not a fixed list in the match form.

<Steps>

### Create the group

Choose **Create group**, enter a name that members will recognise and save.
The group belongs to the game selected in the dashboard.

### Edit the group

Open a group from the list to change its name, description, colour, order,
parent group or Discord link, then save. Add a short description explaining
who belongs in it or how it is used.

### Delete the group

Open the group and choose **Delete group**. Review the affected member count
in the confirmation before deleting. To hide a group only from one match,
uncheck it in that match's **Sign-ups** step instead.

</Steps>

The optional player cap is set separately in a match's **Sign-ups** step or
under **Settings › Match templates › Sign-ups** for future matches. An empty
cap means unlimited. Editing the catalogue does not change those caps.
Both sign-up editors have a **Manage groups** shortcut that opens this
catalogue in a new tab. Return to the original tab after saving. If the
choices have not updated automatically, choose **Refresh groups**
(**Obnovit skupiny** in Czech). Only the group choices refresh, so your
unsaved match or template stays open. Deleted groups are removed from its
selection; the remaining groups keep their selections and caps.

### Link a group to Discord carefully

The optional **Discord role** on a group is an eligibility and import link, not a role-sync switch. It lets a person holding that Discord role select the group’s configured match sign-up option, and it can populate the group during the Discord-member import. It does not automatically grant or revoke the Discord role when you edit an assignment in Logi.

To use it reliably, select a real role from this same Discord server, keep the
bot able to read server members, and ensure that the group is included in the
event's sign-up groups. Only groups from the event's game are available; a
group from another game is never offered. A group can also have an optional
Discord emoji for its sign-up option.

When deleting a group, Logi removes that group from affected primary and secondary assignments before deleting the group. It does not delete the Discord role itself. **Delete group** asks for confirmation first and says how many players have the group as their primary or additional group. Rosters and past events keep the group name they copied.

To create a group, choose the game first; the form appears once a game is picked.

Group-linked roles may overlap other configured Discord roles. Logi does not reject
shared role selections.

## Sharing membership with a website

**Settings → Clan website and sign-in → Find out who is a member** lets an administrator allow an integration
to read one member's current presence, selected Discord role IDs and Logi assignment.
Create a read-only API key with the Discord membership grant first, then enable its
policy and enter the allowed roles for each game. Empty role lists share no roles.
No integration gains access until both gates are configured.

Imported players keep their Logi identity separate from their Discord identity.
Their assignment is included only after an explicit Discord link; a matching
imported ID alone is not a link. Relinking refreshes the old and new membership
projections. Conflicting legacy assignments require an administrator to repair
the duplicate records before an assignment can be shared.

Managed role updates recheck Discord evidence around backend authorization.
If that evidence becomes older than ten seconds, Logi schedules a fresh attempt
instead of applying roles with stale permissions. The operation history shows
the retry; Discord hierarchy restrictions still apply.

Unavailable or stale Discord data is explicitly unknown. The website must enforce
freshness and its own permissions; successful OAuth login, Logi assignment or guild
presence alone does not grant website administration. Disabling the policy or revoking
the key denies subsequent reads. See the [membership handoff](https://github.com/Ninjonik/logi/blob/feat/valkyria-integration/docs/integrations/website/v0.7/README.md)
for the exact-subject API, freshness windows and consumer responsibilities.

## Verified Steam accounts

Open **User settings → Verified Steam account → Verify with Steam** while signed
into Logi. Sign in on Steam and return within ten minutes using the same browser
session. No Steam API key is required. If verification fails, start a new attempt;
wait 30 seconds between attempts. A Steam account can be linked to only one Logi
account at a time. Unlink the current verified account before linking a different one.

Platform IDs typed into the profile or recruitment form remain unverified. The
separate verified account card records proof and the verification time. **Unlink
Steam** stops future attribution while keeping recent link history. Merging
accounts or changing the associated Discord identity requires fresh verification.
This does not grant Discord roles, confirm game ownership or publish a website profile.
