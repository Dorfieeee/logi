# Briefings and stratmaps

## Topic presets

Each preset needs a name and at least one named topic. Each topic contains an
ordered list of Discord-style messages. A message has body text and can carry
uploaded attachments; messages can be reordered. Empty topic titles are
rejected, and empty messages are not useful. The side, map, cap, and notes
fields are useful default briefing context, not enforcement: selecting a preset
does not validate that the event has matching map/side/cap values.

Topic presets are reusable briefing structures. They can contain map-aware topics and help managers prepare consistent information for repeated match or event scenarios. Create them in the workspace’s Topic presets section, then choose a suitable one while editing an event.

## Stratmaps

### Game scope

Every tactical map belongs to a game. In the dashboard, choose **All games** to
see the whole clan, or choose a game below the workspace switcher to work only
with that game's maps, events, and memberships. Existing workspaces and their
existing maps are Hell Let Loose by default. Create Vietnam or Wardogs maps
only after enabling that game in workspace settings.

When you create or open a stratmap from a game-filtered list, Logi keeps that
game selected throughout the create and editor flow. Newly saved maps appear
immediately in both their game-specific list and **All games**.

Vietnam currently exposes placeholder tactical base maps and caps. Wardogs
offers Bakurani, Ozeti, and Zestafona with their tactical basemaps and the
calculator-derived fixed locations for faction HQs, towers, vendors, spawn
boards, and faction spawn zones. The Wardogs icon picker also provides the
distinct Wardogs tactical markers without mixing in the HLL catalog. Wardogs
markers are rendered without the source artwork's glow and follow the selected
marker colour. The same map-marker set is available as squad icons in Wardogs
squad presets. Wardogs tactical basemaps use the high-resolution source tiles,
so managers can zoom in further while planning.
Wardogs maps do not use HLL capture points: the create and editor interfaces
omit point selection. In the editor, managers can independently toggle the
fixed HQ and tower reference layers.
Only workspace managers can create or edit a stratmap, including its drawing
state and metadata. They can switch between slides and select map elements to
inspect or update them. Creating a map without an explicitly saved state starts
it with the default state for its chosen base map. Assigning a stratmap to an
event does not make it the only briefing content and does not publish or notify
it by itself.

<Callout type="warning">
    The reader-facing stratmap route is publicly resolvable by its direct ID.
    Treat stratmap titles, descriptions, drawings, and attached event context as
    shareable with anyone who receives that link; do not place server passwords,
    private channels, or sensitive operational details inside one.
</Callout>

Stratmaps are tactical map resources associated with an event or available in the workspace. Use a clear name and organise information so a player can understand the plan quickly. Select only the maps that are relevant to the event; an overloaded briefing is harder to use under time pressure.

Public stratmap links open in a full-screen editor without the usual Logi header or footer. The browser page itself does not scroll; use the map controls and editor panels within that viewport. On a phone the side panels start closed so the map fills the screen; the buttons in the map's top corners open the details-and-slides panel or the tools panel over the map, and tapping the map closes it again.

The Stratmaps list is paginated and searchable like the other dashboard tables,
and shows the last change in the clan time zone.

### Deleting a stratmap

A manager deletes a stratmap from its editor page with **Delete stratmap**.
The confirmation lists the events that link the stratmap; Logi removes the
stratmap from those events and then deletes it with all its slides. This cannot
be undone. Its public link stops working, including where it was already posted
in a Discord event forum, and uploaded slide or icon images stay in storage.
The website API cannot delete stratmaps; see
[Clan settings](/wiki/configuration/settings).

The editor includes the Maps Let Loose blue, red, orange, yellow, green, purple, white, and grey palette. Select a swatch for the standard tactical colours, or use the final colour control to choose any custom colour. Imported Maps Let Loose green markings use the standard `#00ff00` palette green, while icons retain their friendly blue or enemy red appearance.

When placing an icon, set its size in the tool properties before clicking the
map. HLL icons default to 50, while Wardogs icons default to 25; either default
can be overridden, and already placed icons can still be resized individually.

## Match briefing

### Wardogs match plan

In the match's **Match** step, the map and time of day may remain **TBD / not selected**. HLL maps also allow this empty selection. Wardogs stores the planned time separately from the map, so editing the match preserves both.

After choosing Bakurani, Ozeti or Zestafona, select **Create tactical plan**. Enter a layout name or zone reference. Select **Control Zone**, **Hot Zone**, or one of the selected teams and click the map to position it. X/Y fields provide a keyboard-accessible alternative; coordinates and zone radius are percentages of the map image. Zones and team positions can be removed individually. Changing the map clears the old plan.

The preview uses Logi's existing terrain images, faction headquarters and spawn zones. Team labels follow the selected teams and their factions. The plan is saved with the draft or match, appears in the final review and match overview, and remains editable through the match form. **Download map (SVG)** exports the plan with the terrain image embedded, so it can be shared without an external map-image URL. It does not create a separate Stratmaps resource. The Control Zone is drawn as a square with an editable half-width; the Hot Zone is drawn as a circle with an editable radius. Both are planning conventions over image coordinates, not world-coordinate measurements.

These are manual planning positions. The organiser supplies the agreed control zone, hot zone, layout and radius; the preview does not claim to reconstruct an official server layout or track a moving hot zone. The game's [official overview](https://www.wardogs.com/) describes three teams and a randomized 2×2 km Control Zone, but does not publish the coordinates of each layout. The checked-in map catalogue supplies the terrain and faction bases; no new third-party map images are downloaded for this feature.

For Discord forum output, all of the following are required: the event must be
a match, **Create forum channel** must be enabled, a usable forum category must
be configured, and the bot must have Discord permission to create/edit that
forum channel and posts. The bot then maintains a match-information post,
includes links to selected stratmaps, and creates one forum topic post per
topic-preset topic. Within a topic, it sends the preset's messages in their
saved order, using their body and attachments directly rather than adding
arbitrary embeds.

Forum creation is durable: if Discord creates the event forum but a later
sync step fails, Logi reuses that forum on retry instead of creating another.

Editing a topic preset does not rewrite old forum posts by itself. The event's
topic resync control is available only for a non-concluded event that has both
a forum channel and topic preset. Resyncing can update topic posts and delete
old topic posts that no longer exist in the preset, so review the preset before
using it.

New matches default to **Delete the forum after the match**. After manual or
scheduled conclusion, Logi creates a private debrief thread directly in the
results channel (falling back to event info, then registration) and invites
attending signups and rostered players, including confirmed reserves, excluding
explicit absences. The thread survives deletion of the event card. The bot needs
Create Private Threads, Send Messages in Threads, Read Message History, Pin Messages
and Manage Threads, plus Manage Channels to delete the forum; participants
also need View Channel on the parent channel. A configured parent must be a text
channel. Invitation or thread failures keep the forum intact for retry.
Once the debrief is ready, the event forum and **all its posts, tactics and
attachments are deleted**. Copy anything you need to keep beforehand.

Turn this option off to keep the forum and put its debrief there instead.
Existing matches keep their forum until you explicitly enable deletion. The
workspace's debrief message switch still controls whether a debrief is created;
when disabled, the deletion option removes the forum without a debrief.

From a match or event detail page, open the connected briefing resources. A briefing can combine event details, topic presets, and selected stratmaps, but each must be prepared and saved independently.

<Callout type="info">
    A topic preset helps standardise the structure; it does not guarantee that
    every map, side, mode, or cap value is appropriate. Review the generated
    context for every event.
</Callout>
